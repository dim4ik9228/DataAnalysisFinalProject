# Освіта матері й батька та успішність учнів

Навчальний дослідницький проєкт: реплікація таблиці 8 зі статті Da (2025)
та перевірка стійкості результатів на даних **UCI Student Performance**.

**Автор:** Дмитро Степанюк, МУП-1.

Дослідження відповідає на питання: чи пов’язана вища освіта матері з підсумковими
оцінками учня після врахування освіти батька та інших характеристик, і наскільки
цей зв’язок зберігається за альтернативних умов аналізу?

## Матеріали проєкту

- [Звіт PDF](reports/rendered/report.pdf) — методи, результати, обмеження та повні моделі.
- [Презентація PowerPoint](reports/pptx-redesign/output/osvita_batkiv_prostishe.pptx) — фінальна версія зі спрощеним поясненням перевірок і нотатками доповідача.
- [Текст виступу](reports/pptx-redesign/output/tekst_vystupu_prostishe.md) — окремий сценарій до презентації.
- [Підсумкові висновки](docs/final_conclusions.md) — інтерпретація гіпотез і межі висновків.
- [Результати розрахунків](outputs/tables/) та [графіки](outputs/figures/) — агреговані матеріали аналізу.

Звіт у `reports/rendered/` генерується локально і не входить у Git. Якщо PDF
відсутній у вашій копії, його можна зібрати за інструкцією нижче.

## Основні результати

Математику та португальську мову проаналізовано окремо. Після застосування
фільтра реплікації вибірки містять **390** і **637** записів відповідно.
Підсумкова оцінка G3 вимірюється за шкалою від 0 до 20.

- У повних моделях вища освіта матері порівняно з початковою освітою пов’язана
  з вищою оцінкою приблизно на **2,99 бала з математики** та **1,47 бала з
  португальської**, за врахування освіти батька й інших змінних моделі.
- Прямий тест різниці коефіцієнтів освіти матері та батька не дає достатніх
  доказів цієї різниці. Це не доводить рівність зв’язків або відсутність зв’язку
  з освітою батька.
- Після додавання часу навчання оцінки зв’язку з освітою матері дещо зменшуються,
  але залишаються додатними. Ця зміна має описовий характер і не є тестом медіації.
- Числове порівняння з публікацією дає **82 збіги з 84 перевірок** коефіцієнтів,
  розмірів вибірок і скоригованого R²: сім моделей збігаються повністю, одна — частково.

Аналіз показує **асоціації**, а не причинний вплив освіти батьків.
У моделі M10 залишається розбіжність двох коефіцієнтів `guardian`;
точний тип стандартних похибок автора невідомий. У нашому основному аналізі
використано HC3, а альтернативні оцінки похибок наведено окремо.
Докладне порівняння — у [результатах реплікації](docs/replication_findings.md).
Межі перевірки пов’язаної літератури описано в
[літературному огляді](docs/literature_followup.md).

## Ноутбуки

Основний інтерфейс дослідження — Jupyter Notebook. Порядок читання та виконання:

| Ноутбук | Зміст |
|---|---|
| [00_project_setup.ipynb](notebooks/00_project_setup.ipynb) | Питання дослідження та перевірка середовища |
| [01_data.ipynb](notebooks/01_data.ipynb) | Завантаження, перевірка й підготовка даних |

Вихідні ноутбуки зберігаються в `notebooks/`. Виконані копії з таблицями,
графіками й текстовими результатами — у `outputs/executed/<run_id>/` після
повного запуску. Їх можна переглядати без повторного виконання коду.
Ці копії локальні та ігноруються Git.

## Запуск у Jupyter

Команди виконуються в **PowerShell із кореня репозиторію**. Потрібні Git та uv.
Версію Python **3.13.3** задає `.python-version`, залежності зафіксовано в `uv.lock`.

```powershell
uv sync --locked
uv run --locked python -m ipykernel install --prefix .venv --name parentedu-replication --display-name "Python (parentedu-replication)"
uv run --locked jupyter lab
```

Виберіть ядро **Python (parentedu-replication)**. Виконуйте ноутбуки в порядку
**00 → 01 → 02 → 03 → 04 → 05**, кожен через **Restart Kernel and Run All Cells**.
Активація `.venv` та ручне налаштування `PYTHONPATH` не потрібні.

Під час першого запуску ноутбук 01 завантажує офіційний архів UCI та перевіряє
контрольні суми. Наступні запуски використовують локальний кеш. Змінені raw-файли
не перезаписуються автоматично: невідповідність контрольної суми зупиняє запуск.
Після переміщення репозиторію повторіть налаштування середовища та реєстрацію ядра.

## Повне відтворення

Перевірений маршрут — Windows x64 із Git, uv та встановленим Chrome або Edge.
Перший запуск потребує мережі для отримання даних та інструментів збирання.

```powershell
uv sync --locked
.venv/Scripts/python.exe tools/reporting/setup.py
uv run --locked python scripts/run_project.py
```

Runner послідовно виконує ноутбуки в окремих ядрах, збирає Quarto-звіт і
альтернативні HTML/PDF-слайди, запускає автоматизовані перевірки та порівнює
результати з еталонними виходами репозиторію. PowerPoint-презентація з розділу
«Матеріали проєкту» зберігається окремо і цією командою не перебудовується.

Відтворюваність перевірено незалежним запуском у чистій копії: **267 тестів**,
**46 із 46 дослідницьких виходів** збіглися побайтово.
Деталі середовища, журналів і пакування — у
[посібнику з відтворення](docs/reproducibility.md),
[незалежному аудиті](docs/reviews/P09_reproducibility_review.md)
та [інструкції збирання звіту](reports/README.md).

Для окремого запуску тестів:

```powershell
uv run --locked pytest -q
```
