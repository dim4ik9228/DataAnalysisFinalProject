Дата: 2026-11-05. Статус: **завершено**.

## 1. Мета й межі

Отримати оригінальні файли UCI з відомим походженням, перевірити їх і підготувати окремі відтворювані вибірки для математики та португальської. Результат — не статистичний висновок, а перевірений шлях від вихідного файлу до кожного включеного/виключеного рядка.

У P03 входять завантаження, кеш, SHA-256, схема даних, контроль якості, паспорт, словник змінних, точний фільтр, таблиці N та тести цих правил. Програмну логіку розміщуємо в src/parentedu, пояснення й виклики — в notebooks/01_data.ipynb.

У P03 не входять повний EDA й графіки зв'язків (P04), матриці регресорів і моделі (P05), виконання robustness (P06), підтвердження гіпотез. Опис кодів, пропусків, нульових оцінок, дублікатів і чисельності — допустима технічна перевірка якості.

Цей план створено до завантаження даних. Фактичний підсумок реалізації наведено в розділі8; початкові очікування нижче збережено для простежуваності.

## 2. Вхідний стан і незмінні правила

Вхідні файли: AGENTS.md, README.md, docs/architecture.md, docs/replication_protocol.md, configs/analysis.toml, docs/original_methods.md, docs/sources.md, data/reference/table8_models.csv, src/parentedu/paths.py, src/parentedu/config.py, шаблон notebooks/01_data.ipynb, .gitignore.

- Офіційне джерело: [UCI Student Performance](https://archive.ics.uci.edu/dataset/320/student+performance), DOI10.24432/C5TG7T. Посилання завантаження та актуальну ліцензію звірити під час реалізації; не брати довільну Kaggle-копію.
- Очікувані вихідні обсяги за описом джерел: mat395, por649. Це контрольні орієнтири, не вже перевірені нами N.
- Авторські N таблиці8 після фільтра: mat390, por637. Брати з перевірених еталонів та звіряти з конфігом.
- Точна вибірка: Medu>=1 **і** Fedu>=1; G3=0 залишити. Ваг, імпутації, train/test та інших виключень немає.
- Зберігати оригінальні коди й порядок, не об'єднувати предмети як незалежних учнів. Ніякого автоматичного видалення дублікатів.
- Підготовка не повинна міняти протокол, еталони чи пороги, щоб отримати очікуваний N.
- Невідомий авторський SE і відкрита вимога3–5 citing/checking робіт не розв'язуються даними P03; застереження P02 залишаються видимими.

## 6. Ризики та нерозв'язані питання

| Ризик / питання | Правило |
|---|---|
| Архів змінився або отримано old-версію | URL/DOI/вміст/хеші; не підміняти мовчки |
| Missing або невідомий код | Помилка схеми й діагностика, без імпутації/тихого drop |
| Незбіг390/637 | Аудит джерела й маски, не додаткові виключення |
| Схожі/дублікатні записи | Звітувати, зберігати; record_id не є person_id |
| Втрата освіти0 | Зберігати повний валідований шар для R1 |
| Випадковий drop G3=0 | Явний інваріант і тест |
| CSV втрачає categorical типи | Оригінальні коди + схема; read-back validation |
| Зміна raw при повторному запуску | Hash-check, cache-by-default, окремі acquisition/run metadata |
| Малі майбутні підгрупи | Показати кількості/ризик; не об'єднувати категорії задля оцінювання |

На початку P03 немає попередньо перевіреного хешу учнівського архіву. Після отримання його фіксуємо у tracked provenance для наступних виконавців. Перший SHA-256 фіксує отримані байти, але сам по собі не доводить тотожність даним автора. Походження, схема, N і подальша реплікація дають різні рівні перевірки.
