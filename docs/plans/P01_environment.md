# P01. Середовище та запуск — детальний план

Дата: 2026-11-05. Статус: **завершено**.
Обсяг: S, орієнтовно одна робоча сесія; проблеми Git або сумісності пакетів можуть збільшити обсяг.
Загальний план: [roadmap](../roadmap.md). Виконавець: основний агент.

## 1. Мета та межі

Підготувати відтворюване Python-середовище і підтвердити, що ноутбук 00 працює з чистого ядра у перейменованому проєкті. З'ясувати стан Git і забезпечити подальшу фіксацію роботи.

До P01 входять: інструменти, залежності, editable-встановлення локального пакета, ядро Jupyter, технічний preflight, коротка документація та перевірка ролей агентів.

До P01 не входять: завантаження UCI, EDA, оцінювання моделей, зміна наукових гіпотез, транскрипція таблиці 8, звіт і презентація. Повний runner усіх ноутбуків залишається в P09; тут перевіряємо лише 00.

6. Перевірити .gitignore: середовище, кеші, локальні логи й виконані ноутбуки ігноруються; вихідні файли, .python-version і uv.lock — ні.

**Вихід:** короткий діагностичний запис у docs/decisions.md; за потреби мінімальні виправлення шляхів/.gitignore або локальної Git-конфігурації.

**Приймання:** git status стабільно працює в контексті проєкту, корінь правильний; відомо, що зміни не втратили історію. Якщо причину усунути не вдалося, записати конкретний блокер: решту технічної роботи можна продовжити, але P01 не позначати завершеною.

### P01.2. Python і фіксація залежностей

**Рішення:** почати з наявного Python 3.13.3. Якщо resolver або пакети несумісні, спершу встановити причину. Перехід на іншу підтримувану версію 3.11–3.13 — явне рішення з обґрунтуванням; не послаблювати межі пакетів довільно.

**Дії:**
1. Записати версії Python та uv. Перевірити поточний pyproject.toml, групу dev і build-system.
2. Зафіксувати точну версію Python у .python-version. Створити .venv у корені та uv.lock. Встановлювати пакети лише в середовище проєкту.
3. Переконатися, що uv встановив parentedu-replication як editable-пакет, а не лише сторонні залежності.
4. Перевірити актуальність lock-файлу і повторну синхронізацію без його зміни.

**Орієнтовні команди для реалізації** (перед виконанням звірити з локальною версією uv):

```powershell
python --version
uv --version
uv python pin 3.13.3
uv sync
uv lock --check
uv sync --locked
```

Після фіксації залежностей перевірки запускати через `uv run --locked ...`. Прапорець locked має зупинити запуск, якщо метадані потребують оновлення lock-файлу.

**Вихід:** .python-version, uv.lock, локальна .venv; pyproject.toml змінювати лише за доведеної потреби.

**Приймання:** залежності успішно встановлено, lock відповідає pyproject, повторний sync не змінює lock. Перевірка sys.executable показує .venv, а parentedu.__file__ — src/parentedu цього проєкту. Не використовувати sys.path-вставки або PYTHONPATH як заміну встановленню пакета.

**Приймання:** клітинка ноутбука підтверджує sys.executable із .venv; імпорт і ROOT правильні без ручного налаштування абсолютних шляхів.

## 6. Ризики та рішення

| Ризик | Дія |
|---|---|
| Неправильний контекст Git після перейменування | Діагностувати env/config, зберегти .git; не обходити повторним init |
| Старий cwd чату або обмеження запису | Явно використовувати актуальний workdir; дозволи на новий шлях вирішувати штатним механізмом |

| Помилки кодування українського тексту у Windows | Файли UTF-8; для Python stdout явно використовувати UTF-8 під час перевірок |
